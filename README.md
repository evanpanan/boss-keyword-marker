# BOSS直聘 · 关键词标注器（只标注，不点击）

> **v2.0 起的重要变更**：由于 BOSS 直聘明确警告「自动化打招呼会被封号」，**自动点击能力已从代码层面整个移除**。
> 插件现在只负责把命中关键词的人圈出来、把关键词所在位置标出来，打招呼由你人工完成。

在 BOSS 直聘**招聘端**筛选命中关键词（默认 `美股` / `投资者关系` / `IR`）的候选人，
按命中数量分三档配色圈出，并把页面文本里每一处关键词的位置都标出来。
勾选 QS 名校后，**QS 前 50 / 前 100 大学的简历会额外套一圈校色光环并被排到清单最前面**。

---

## 一、安全边界（这是本版本的核心）

插件**只做只读操作**，从代码层面就不具备触发 BOSS 按钮的能力：

| 项目 | 情况 |
|---|---|
| 派发鼠标/键盘事件 | ❌ 完全没有。代码中不含 `dispatchEvent` / `MouseEvent` / `PointerEvent` / `KeyboardEvent` |
| 点击页面元素 | ❌ 没有 `element.click()`，不碰页面上任何按钮 |
| 打开候选人详情 | ❌ 不会自动打开详情抽屉（你自己点开，插件只负责标注） |
| 翻页 / 自动滚动 | ❌ 没有 `scrollTo` / `scrollBy`，页面靠你自己滚 |
| 修改页面 DOM | ❌ 不插入、不修改、不隐藏页面上任何原有元素 |
| 网络请求 | ❌ 不发起任何请求；接口数据是「被动读取」页面自己发出的响应 |

标注画在一个**独立的固定定位悬浮层**里（`pointer-events:none`，鼠标穿透），
所以它既不会挡住你的操作，也不会让页面结构发生变化。
关键词位置是用 `Range.getClientRects()` **只读**取坐标的，不包裹、不替换任何页面节点。

唯二会动到页面的地方，且**都由你主动触发**：
1. 你在浮层里点「定位」→ 仅调用 `scrollIntoView` 把该候选人滚到视野中央
2. 你在浮层角标上点「✓」→ 仅写入本地存储，标记为已打招呼

## 二、框色分级（v3 新增）

框的颜色由**命中的「不同关键词」个数**决定 —— `IR` 在同一人身上出现 5 次也只算 1 个词。

| 命中数量 | 颜色 | 含义 |
|---|---|---|
| 1 个 | 🔵 蓝 `#2f6fed` | 沾到一个词 |
| 2 个 | 🟠 橙 `#e8890c` | 命中两个词 |
| 3 个及以上 | 🔴 红 `#d93025` | 强匹配，优先看 |

- 角标会写清楚，例如 `命中 3 词 · 美股/IR/投资者关系`
- 已打过招呼的人：框外多一圈**绿色描边**，角标转绿显示 `已打招呼 · …`（框色仍保留分级色，不丢信息）
- 右下角浮层顶部有分级计数，弹窗里也有三档人数

## 三、关键词位置标注（v3 新增）

除了圈人，插件还会**把页面文本里每一处关键词的位置标出来**（淡色底 + 下划线）。

- **默认开启**，页面任何位置的命中词都会被标出来
- **打开候选人详情浮层后同样持续标注** —— 你手动点开详情，放大/滚动，标注会跟着走
- 详情浮层整体还会套一个**虚线区域框**，角标显示 `详情命中 N 词 · …`，颜色同样按分级
- 详情里的命中词会自动**回填给同名候选人** —— 如果卡面上只看到 1 个词、详情里其实有 3 个，卡片框会从蓝升到红
- 卡片内部默认**不**逐词高亮（卡片已经有整块框，再逐词会花），需要的话在弹窗里勾「卡片内部也逐词高亮」

> 顺带说一句：标注「关键词在哪」用的是只读的 Range 取坐标，所以我们不需要去点开详情、也不需要改动详情里的 DOM。
> 详情是你自己点开的，插件只是把已经渲染出来的文字量了一下位置。

## 四、QS 名校格外标记（v4 新增）

在扩展弹窗里勾选 **QS 前 50 大学** / **QS 前 100 大学** 后，名校背景的简历会被「格外标记」。

**为什么值得单独标**：关键词命中的是「做什么的」，名校标记的是「什么背景」。
两个维度叠在一起看，就能快速分出「名校 + 强相关」「名校 + 弱相关」「普通院校 + 强相关」这几种人。

### 标记表现

| 元素 | 前 50 名校 | 前 100 名校 |
|---|---|---|
| 卡片框外圈 | 🟣 紫色光环 `#7c3aed` | 🔵 青色光环 `#0e7490` |
| 角标徽标 | `🎓 QS50`（白底紫字） | `🎓 QS100`（白底青字） |
| 清单整行 | 紫底 + 紫侧条 + 紫字 | 青底 + 青侧条 + 青字 |

- **光环是叠加的，不是替换**：如果这个人同时命中关键词，卡片边框仍然是关键词分级色（蓝/橙/红），
  名校信息由外圈光环承载 —— 两个维度的信息都不丢。
- **没有关键词也照样标**：勾选之后，即使一个关键词都没命中，只要是名校简历也会被单独圈出来
  （这时候整个框用校色，角标直接显示学校名，例如 `🎓 QS50 清华大学`）。
- **清单排序**：QS 前 50 → QS 前 100 → 关键词命中数。打开面板，名校的人永远在最上面。
- **详情浮层同样生效**：详情里的虚线区域框会套上校色光环，角标显示 `详情 · 🎓 清华大学 · 3 词`；
  详情里读到的学校会**回填给同名候选人**（列表上看不出名校，打开详情后卡片自动套上光环）。

### 名单与匹配规则

名单硬编码在 `extension/qs-rankings.js`，共 **QS 2026 世界大学排名前 100 的 100 所大学、428 个别名**。

- 每所学校收录：中文校名（+ 常见中文简称如 港大 / 浙大 / 北大）+ 英文官方校名 + 英文常用缩写
- **英文别名**：大小写不敏感 + 整词边界 —— `UCL` 不会误命中 `UCLA`，`NTU` 不会命中 `Ntuxxx`
- **中文别名**：直接子串匹配
- **跨校后缀保护**：`City University of Hong Kong` 里含 `University of Hong Kong`，
  「城大」的人不会被同时标成「港大」（英文后缀关系在做索引时自动检测并加负向后顾）
- **简称歧义处理**：`NTU` 既是南洋理工也是台湾大学的缩写 —— 这种情况会显示成 `🎓 QS? NTU`，
  并取排名更优的那所（南洋理工 QS12）。只要简历里写了全名，问号就消失。
- 排名只到 100。**不在名单里的学校（如 KAIST、东北大学）不会被标记** —— 这是刻意的，
  避免把「排名 101-200」也混进「QS 前 100」里。

> **想换名单 / 换年份**：直接编辑 `qs-rankings.js` 的数组即可（字段：`r` 排名、`zh` 中文名、
> `en` 英文名、`a` 别名数组、`c` 国家地区），其他代码不用动。删除某行就等于把该校移出名单。

### 性能

匹配是纯本地文本比对，**不联网、不查任何外部接口**。实测单次匹配耗时：

| 场景 | 单次耗时 |
|---|---|
| 普通简历卡片（无校名） | 0.005 ms |
| 含名校的卡片 | 0.023 ms |
| 3600 字长文本（无校名） | 0.059 ms |

一页 30 位候选人全都没有名校时，一轮扫描开销约 **0.2ms** —— 等于没有开销。
（实现上先用一个合并正则做粗筛，文本里连一个校名都没出现就直接跳过整轮比对。）

## 五、安装

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本目录下的 `extension` 文件夹
4. 安装后在工具栏固定该扩展

> **如果你之前装过 v1（自动打招呼版）**：请先在 `chrome://extensions` 里**移除**它，
> 再加载这一版，避免两个版本同时注入。加载后记得刷新 BOSS 页面。

## 六、使用

1. 打开 BOSS 直聘招聘端，进入「推荐牛人」页面
2. 页面右下角会自动出现「关键词标注」浮层，命中的人立刻被框出
3. 你自己滚页面、切筛选、翻页，标注会**自动跟着更新**（每 1.2 秒只读重扫一次）
4. **优先处理红色框的人**，自己点「打招呼」
5. 点完按钮会变成「继续沟通」，插件检测到后**自动打勾**；也可以手动点「标记」
6. 浮层里的「定位」可以把某个人滚到视野中央

## 七、参数（扩展弹窗里改）

| 参数 | 默认 | 说明 |
|---|---|---|
| 关键词 | 美股,投资者关系,IR | 逗号分隔，改动后立即生效 |
| 英文短词匹配 | 整词 | `IR` 不会误命中 `first` / `their` / `IRR` / `irq` |
| **QS 前 50 大学** | **关** | 名校简历外套紫色光环 + 🎓 QS50·校名 徽标 + 清单整行变紫 |
| **QS 前 100 大学** | **关** | 含前 50；51–100 名用青色。勾上后没关键词的名校简历也会被标出来 |
| 命中角标 | 开 | 关掉后只留框 |
| 标注关键词位置 | **开** | 页面文本里每处关键词都高亮，详情浮层同理 |
| 卡片内部也逐词高亮 | 关 | 开了以后卡片里也会逐词标 |

> 两个 QS 选项是**独立**的：只勾「前 50」就只标前 50；勾了「前 100」则 1–100 名都会标，
> 其中 1–50 名仍按前 50 档显示（紫色），51–100 名按前 100 档显示（青色）。

## 八、免费筛选（v5 新增 —— 对齐 BOSS 的 VIP 筛选）

BOSS 的「年龄 / 院校 / 活跃度 / 专业」筛选要开 VIP。但候选人卡片上**本来就免费显示着这些信息**，
VIP 收钱收的只是「按条件筛掉」这个动作。本插件不去"筛掉"任何人，只**给卡片加一圈灰色虚线框 + 左上角
「✗不符 · 原因」小灰标**——内容一个字都不遮、不变灰，筛不筛由你自己决定。

| VIP 筛选项 | 本插件对应 | 实现方式 | 可靠性 |
|---|---|---|---|
| 年龄区间 | ✅ 年龄 25–35 岁 | 读卡片文本/接口里的「28岁」 | 高 |
| 院校 985 | ✅ 院校 = 985 工程 | 39 所名单 + 常用简称，本地匹配 | 高 |
| 院校 211 | ✅ 院校 = 211 工程 | 985 + 73 所，本地匹配 | 高 |
| 院校 QS 100 | ✅ 院校 = QS 前 100 | 复用 v4 名单（境内外都算） | 高 |
| 院校 QS 500 | ⚠️ 未做 | 需要 400+ 校名数据，有可靠来源后可加 | — |
| 院校 双一流 | ⚠️ 未做 | ≈ 211 + 约 30 所新增，可按需加 | — |
| 院校 留学 | ⚠️ 近似 | 可用「QS 前 100 境外院校」近似 | 中 |
| 院校 公办本科 | ❌ 做不了 | 公办/民办在卡片文本里判不出来 | — |
| 活跃度 | ✅ 五档（刚刚/今日/3日/本周/本月） | 卡片上直接显示这些字样 | 高 |
| 性别 | ❌ 已移除（v5.3） | BOSS 列表页与接口都不提供可靠性别数据，推断会错，**故整个功能删除** | — |
| 专业 | ✅ 关键词（任一命中） | 文本匹配，你自己填 | 高 |
| 近期没看过 | ❌ 做不了 | 浏览历史在 BOSS 侧，页面读不到 | — |
| 与同事交换简历 | ❌ 做不了 | 同上 | — |
| 跳槽频率 | ❌ 做不了 | 需要完整工作经历时间线，列表卡片只有当前一段 | — |

**使用**：扩展弹窗「免费筛选」区设置条件 → 不符的卡片加灰色虚线框 + 「✗不符 · 原因」灰标、
面板显示「符合筛选 X/Y」、符合的人角标带上条件标签（如 `命中 · IR · 985·28岁`）、清单里符合的排前面。

**QS 名校识别**：徽标会带上校名（`🎓 QS50·香港中文大学`），方便一眼核对识别依据。
分校区不算本部——简历写「香港中文大学（深圳）」不会被当作 QS 前 50 的港中文本部。

**别名防误伤**：中文简称做了歧义保护——「湖北大学」不会命中北大、「佛山/燕山大学」不会命中山大、
「杭州电子科技大学」不会命中电子科大、「西南政法」不会命中法大、「济南大学」不会命中南大（该简称已删）。
保护表在 `content.js` 的 `CN_ALIAS_GUARDS`，发现误伤往里加一行即可。

## 九、判定依据（为什么它能标得准）

1. **卡片文本**：直接读候选人卡片的可见文字（求职期望、公司、职位、优势摘要、标签…）
2. **接口增强**：`inject.js` 在 MAIN world 被动挂钩 `fetch` / `XMLHttpRequest`，
   把页面自己请求的 `rec/geek/list` 响应解析成 `{geekId | 姓名: 可读文本}` 映射，
   写到 `<html data-bag-geek-text>` 供标注层读取。
   **这一步只是读页面已经拿到的数据，不发起任何额外请求。**
   好处是能补上卡片上被省略号截断的「优势」全文，减少漏人。
3. **详情回填**：你手动打开详情后，详情里的命中词会并入同名候选人的命中集合，等级随之提升。

## 十、诊断

如果出现「命中明显不对」或「一个都没标出来」，点扩展图标 → **诊断本页**，
它会逐个 frame 返回：卡片数量、页面文本长度、接口捕获到的候选人数、命中关键词、
**命中的 QS 校名**、当前按钮文案、卡片文本样本。把这段结果贴出来即可定位问题。

重点关注两个数：
- **接口候选人数**：为 0 说明 `inject.js` 挂钩没生效，此时只靠卡片文本匹配，准确率会下降
- **QS 校名**：如果这里为空但你明明看到某人是名校，说明该校名还没进名单 → 告诉我，或者直接往
  `qs-rankings.js` 里加一行

## 十一、已知边界

- 只标注**当前页面已加载的**候选人。BOSS 的列表是滚动加载的，没滚到的部分不在页面上，自然也不会被标注——
  往下滚，标注会自动补上。
- 列表页被全屏弹窗遮住时，卡片框会自动收起（避免糊在弹窗上），但**详情框与关键词高亮照常显示**。
- 详情浮层的识别用的是启发式（找视口内面积较大的 fixed/absolute 浮层）。如果 BOSS 换了实现方式导致
  详情框没出现，**文字高亮仍然有效**，只是少了那圈虚线框。
- 如果 BOSS 改动页面结构（卡片类名、接口地址），需要相应更新 `content.js` 的
  `collectCards` / `findDetailRoot` 选择器和 `inject.js` 的接口匹配规则。

## 十二、文件结构

```
extension/
├── manifest.json      扩展清单（MV3）
├── qs-rankings.js     QS 2026 前 100 名单（纯数据，想改名单只动这里）
├── inject.js          MAIN world：被动读取列表接口响应 → <html> 属性
├── content.js         只读扫描 + 悬浮层标注（分级框 / 校色光环 / 详情框 / 关键词位置）+ 右下角浮层面板
├── popup.html         扩展弹窗界面
└── popup.js           弹窗逻辑（配置读写、三档计数、QS 计数、重新扫描、诊断）
```

外层还有一个 `preview.html`：**不用装扩展就能看的配色预览页**（静态示意，改配色前先在这看效果）。
